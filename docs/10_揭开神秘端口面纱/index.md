## 10.1 概述

在网络安全和系统管理中，我们经常需要快速定位网络中开放了特定**端口**的**服务**器。例如：

!!! example "场景1：安全审计"
    你是一名安全工程师，需要检查内网中是否有数据库**服务**暴露在不该开放的**端口**上。你需要快速找出所有开放了**MySQL**、**PostgreSQL**、**MongoDB**、**Redis**等数据库**端口**的服务器。

???+ info "场景2：网络故障排查"
    公司内网的**DNS**服务器响应缓慢，网络管理员需要扫描整个网段，找出所有开放了53**端口**的设备，确认是否存在**DNS**服务器配置错误。

!!! warning "场景3：合规性检查"
    根据安全策略，生产环境的Web服务器只能开放80（**HTTP**）和443（**HTTPS**）**端口**。安全团队需要定期**扫描**服务器，检测是否有机器的22（**SSH**）、3389（**RDP**）、21（**FTP**）等管理**端口**对外开放。

这些场景的共同需求是：**在目标网络中，快速找到开放了特定端口的服务器**。这正是本章要解决的问题。

**Nmap**作为最强大的网络扫描工具，提供了灵活的端口指定方式，让我们可以精确控制扫描哪些**端口**，从而高效地完成上述任务。

## 10.3 背景知识

### 10.3.1 端口的基本概念

在TCP/IP协议中，**端口**（Port）是用于区分不同网络服务的逻辑编号，范围是0-65535。

| 端口范围 | 名称 | 说明 |
|---------|------|------|
| 0-1023 | 知名端口（Well-known Ports） | 由IANA分配给常用服务，如HTTP(80)、SSH(22) |
| 1024-49151 | 注册端口（Registered Ports） | 可由用户进程使用，部分被注册服务占用 |
| 49152-65535 | 动态/私有端口（Dynamic/Private Ports） | 通常由客户端程序随机选用 |

### 10.3.2 常用服务与默认端口对照表

| 服务名称 | 端口号 | 协议 | 说明 |
|---------|--------|------|------|
| **HTTP** | 80 | TCP | 超文本传输协议（明文） |
| **HTTPS** | 443 | TCP | 加密的HTTP协议 |
| **SSH** | 22 | TCP | 安全远程登录 |
| **FTP** | 21 | TCP | 文件传输协议（控制连接） |
| **FTP-DATA** | 20 | TCP | FTP数据传输 |
| **SMTP** | 25 | TCP | 简单邮件传输协议 |
| **DNS** | 53 | TCP/UDP | 域名解析服务 |
| **MySQL** | 3306 | TCP | MySQL数据库 |
| **PostgreSQL** | 5432 | TCP | PostgreSQL数据库 |
| **MongoDB** | 27017 | TCP | MongoDB数据库 |
| **Redis** | 6379 | TCP | Redis键值数据库 |
| **RDP** | 3389 | TCP | 远程桌面协议（Windows） |
| **Nginx** | 80/443 | TCP | Nginx Web服务器（通常） |
| **Apache** | 80/443 | TCP | Apache Web服务器（通常） |
| **Tomcat** | 8080 | TCP | Tomcat应用服务器 |

???+ info "注意"
    上述端口是服务的"默认"端口。实际部署中，管理员可能会修改默认端口以提高安全性。例如，将SSH改为2222端口，将MySQL改为13306端口等。

### 10.3.3 端口状态的含义

Nmap扫描端口后，会报告端口的**状态**。理解这些状态对于分析扫描结果至关重要。

!!! info "端口状态详解"
    - **open（开放）**：目标机器上该端口有应用程序正在监听连接请求。这是最值得关注的状态。
    
    - **closed（关闭）**：端口可访问，但没有应用程序监听。通常表示主机在线，但该服务未运行。
    
    - **filtered（被过滤）**：Nmap无法确定端口是否开放，因为数据包被防火墙、过滤器拦截，未收到响应。
    
    - **unfiltered（未过滤）**：端口可访问，但无法确定open还是closed。通常出现在ACK扫描中。
    
    - **open|filtered**：无法确定是open还是filtered。
    
    - **closed|filtered**：无法确定是closed还是filtered。

### 10.3.4 端口与服务的关系

一个**端口**对应一个**服务**，但一个**服务**可能对应多个**端口**：

!!! example "示例"
    - **Nginx** 或 **Apache** Web服务器通常监听80（HTTP）和443（HTTPS）端口
    - **Tomcat** 应用服务器默认监听8080端口
    - 一台服务器可能同时运行多个服务，如同时开放22（SSH）、80（HTTP）、3306（MySQL）

理解这种关系，有助于我们：
1. 通过**扫描**特定端口来发现特定服务
2. 通过服务**检测**来验证端口上运行的具体应用程序
3. 在安全审计中发现违规开放的服务

## 10.4 Nmap参数详解

Nmap提供了多种方式来指定要扫描的**端口**。掌握这些参数，是实现精确扫描的关键。

### 10.4.1 基本端口指定参数 `-p`

`-p` 参数用于指定要扫描的端口。

!!! info "语法"
    ```bash
    nmap -p <port specification> <target>
    ```

**示例1：扫描单个端口**

```bash
# 扫描192.168.1.100的80端口（HTTP）
nmap -p 80 192.168.1.100
```

**示例2：扫描多个指定端口**

```bash
# 扫描常见Web端口
nmap -p 80,443,8080 192.168.1.100
```

**示例3：扫描端口范围**

```bash
# 扫描1-100号端口
nmap -p 1-100 192.168.1.100
```

**示例4：扫描所有端口**

```bash
# 扫描所有65535个端口（耗时较长）
nmap -p- 192.168.1.100

# 等价于
nmap -p 1-65535 192.168.1.100
```

**示例5：组合使用**

```bash
# 扫描1-100和443端口
nmap -p 1-100,443 192.168.1.100
```

### 10.4.2 快速扫描参数 `--top-ports`

如果你只想扫描最常见的端口，可以使用 `--top-ports` 参数。

!!! info "语法"
    ```bash
    nmap --top-ports <number> <target>
    ```
    
    Nmap内置了一个常见端口列表（按使用频率排序）。`--top-ports` 会扫描排名前N的端口。

**示例：扫描最常见的100个端口**

```bash
nmap --top-ports 100 192.168.1.100
```

???+ info "提示"
    `--top-ports 100` 通常足以发现大多数常用服务，且扫描速度远快于全端口扫描。

### 10.4.3 快速扫描模式 `-F`

`-F` (Fast scan) 参数表示快速扫描，仅扫描默认的最常见100个端口。

```bash
nmap -F 192.168.1.100
```

等价于 `--top-ports 100`。

### 10.4.4 跳过主机发现直接扫描 `-Pn`

当目标主机有**防火墙**保护，禁止ICMP ping时，需要使用 `-Pn` 参数跳过主机发现，直接进行端口扫描。

```bash
# 不进行主机发现，直接扫描端口
nmap -Pn -p 80,443 192.168.1.100
```

!!! warning "注意"
    使用 `-Pn` 时，Nmap会假设所有目标主机都在线，这可能会增加扫描时间。

### 10.4.5 服务版本检测 `-sV`

`-sV` 参数用于检测开放**端口**上运行的**服务**的具体版本信息。

```bash
# 扫描80端口并检测服务版本
nmap -p 80 -sV 192.168.1.100
```

**预期输出示例：**

```
PORT   STATE SERVICE VERSION
80/tcp open  http    nginx 1.18.0
```

从输出可以看到，80端口开放，运行的是**Nginx** 1.18.0版本。

### 10.4.6 操作系统检测 `-O`

`-O` 参数尝试识别目标主机的操作系统类型。

```bash
nmap -O -p 22,80 192.168.1.100
```

### 10.4.7 综合扫描参数组合

在实际使用中，我们经常组合多个参数以实现更全面的扫描。

!!! info "常用组合"
    ```bash
    # 综合扫描：端口扫描 + 服务版本检测 + 操作系统检测
    nmap -p 1-1000 -sV -O 192.168.1.100
    
    # 跳过主机发现，扫描常见端口，检测服务版本
    nmap -Pn --top-ports 100 -sV 192.168.1.0/24
    ```

### 10.4.8 针对特定服务的端口扫描策略

针对不同的服务，我们可以设计专门的扫描策略：

| 目标服务 | 推荐端口 | 扫描命令示例 |
|---------|---------|-------------|
| Web服务（HTTP/HTTPS） | 80, 443, 8080 | `nmap -p 80,443,8080 -sV <target>` |
| SSH服务 | 22, 2222 | `nmap -p 22,2222 -sV <target>` |
| 数据库服务 | 3306, 5432, 27017, 6379 | `nmap -p 3306,5432,27017,6379 -sV <target>` |
| DNS服务 | 53 | `nmap -p 53 <target>` |
| 邮件服务 | 25, 465, 587, 110, 143 | `nmap -p 25,465,587,110,143 <target>` |
| 远程桌面 | 3389 | `nmap -p 3389 <target>` |

## 10.5 实战演练

本节通过5个实际场景，帮助您掌握如何使用Nmap寻找特定端口的服务器。

!!! warning "法律声明"
    本章所有示例仅用于授权环境下的学习和测试。未经授权扫描他人网络属于违法行为。请确保在自己的测试环境或获得书面授权的目标上进行扫描。

### 练习1：扫描网段内开放SSH服务的服务器

**场景**：管理员需要找出内网中所有开放了SSH服务（22端口）的Linux服务器，以便进行集中管理。

**命令**：

```bash
# 扫描整个C段，查找开放22端口的主机
nmap -p 22 192.168.1.0/24
```

**预期输出**：

```
Nmap scan report for 192.168.1.10
Host is up (0.0023s latency).
PORT   STATE SERVICE
22/tcp open  ssh

Nmap scan report for 192.168.1.25
Host is up (0.0018s latency).
PORT   STATE SERVICE
22/tcp open  ssh

Nmap scan report for 192.168.1.88
Host is up (0.0031s latency).
PORT   STATE SERVICE
22/tcp closed ssh

...
```

**结果分析**：

- `192.168.1.10` 和 `192.168.1.25` 的22端口状态为 **open**，说明这两台主机开放了SSH服务
- `192.168.1.88` 的22端口状态为 **closed**，说明主机在线但未运行SSH服务

???+ tip "提高效率"
    如果网段较大，可以加上 `-n` 参数禁用DNS解析，加快扫描速度：
    ```bash
    nmap -n -p 22 192.168.1.0/24
    ```

### 练习2：检测Web服务器使用的Web服务软件

**场景**：安全审计需要确认公司Web服务器使用的是 **Nginx** 还是 **Apache**，以及具体的版本号。

**命令**：

```bash
# 扫描80和443端口，并检测服务版本
nmap -p 80,443 -sV www.example.com
```

**预期输出**：

```
PORT    STATE SERVICE  VERSION
80/tcp  open  http     nginx 1.20.2
443/tcp open  ssl/http nginx 1.20.2
```

**结果分析**：

- 80和443端口均为 **open** 状态
- 服务均为 **HTTP**
- 具体版本为 **Nginx** 1.20.2

!!! info "扩展"
    如果需要更详细的服务信息，可以加上 `--version-intensity 9` 参数增强版本检测强度：
    ```bash
    nmap -p 80,443 -sV --version-intensity 9 www.example.com
    ```

### 练习3：扫描数据库服务器的常见端口

**场景**：安全团队需要检查数据库服务器是否违规开放了对外**连接**端口。需要检查 **MySQL**（3306）、**PostgreSQL**（5432）、**MongoDB**（27017）、**Redis**（6379）的默认端口。

**命令**：

```bash
# 扫描常见数据库端口
nmap -p 3306,5432,27017,6379 -sV db-server.internal
```

**预期输出**：

```
PORT      STATE  SERVICE     VERSION
3306/tcp  open   mysql       MySQL 8.0.28
5432/tcp  closed postgresql
27017/tcp open   mongodb     MongoDB 5.0.6
6379/tcp  open   redis       Redis 6.2.6
```

**结果分析**：

- **MySQL** 3306端口 **open**，版本8.0.28
- **PostgreSQL** 5432端口 **closed**，未运行
- **MongoDB** 27017端口 **open**，版本5.0.6
- **Redis** 6379端口 **open**，版本6.2.6

!!! danger "安全风险"
    如果数据库端口对外开放，且未配置强密码或访问控制，可能导致数据泄露。建议：
    1. 将数据库端口绑定到127.0.0.1（仅允许本地连接）
    2. 配置防火墙规则，限制访问源IP
    3. 使用强密码和SSL/TLS加密连接

### 练习4：批量扫描并识别所有开放端口及对应服务

**场景**：对一台未知服务器进行全面审计，需要找出所有开放的**端口**及对应的**服务**。

**命令**：

```bash
# 扫描所有端口，检测服务版本和操作系统
nmap -p- -sV -O -A 192.168.1.100
```

**参数说明**：
- `-p-`：扫描所有65535个端口
- `-sV`：检测服务版本
- `-O`：操作系统检测
- `-A`：全面扫描（包含脚本扫描、traceroute等）

**预期输出（部分）**：

```
PORT     STATE SERVICE    VERSION
22/tcp   open  ssh        OpenSSH 8.2p1 Ubuntu 4ubuntu0.5
80/tcp   open  http       Apache httpd 2.4.52
443/tcp  open  ssl/http   Apache httpd 2.4.52
3306/tcp open  mysql      MySQL 8.0.28
8080/tcp open  http-proxy Apache Tomcat 9.0.62
...
OS details: Linux 5.4.0 - 5.15.0
```

**结果分析**：

该服务器开放了多个端口：
- 22：**SSH**服务（OpenSSH）
- 80/443：**HTTP/HTTPS**服务（**Apache**）
- 3306：**MySQL**数据库
- 8080：**Tomcat**应用服务器

### 练习5：绕过防火墙扫描被过滤的端口

**场景**：目标服务器前有**防火墙**防护，常规扫描显示所有端口 **filtered**。需要使用绕过技术来**检测**真实开放的端口。

**命令1：使用TCP ACK扫描（不易被防火墙拦截）**

```bash
# TCP ACK扫描，用于发现未被防火墙完全阻断的端口
nmap -sA -p 80,443 192.168.1.50
```

**命令2：分片扫描（绕过某些防火墙）**

```bash
# 将IP数据包分片，绕过简单的包过滤防火墙
nmap -f -p 80,443 192.168.1.50
```

**命令3：使用诱饵技术（隐藏真实扫描源）**

```bash
# 使用诱饵IP混淆扫描来源
nmap -D RND:10 -p 80,443 192.168.1.50
```

**命令4：调整扫描时序（慢速扫描绕过IDS/IPS）**

```bash
# 使用T0（最慢）时序，降低被检测概率
nmap -T0 -p 80,443 192.168.1.50
```

!!! warning "注意"
    防火墙和入侵检测系统（IDS/IPS）会影响扫描结果的准确性。如果扫描结果显示所有端口均为 **filtered**，可能说明：
    1. 目标主机不在线
    2. 防火墙完全阻断了扫描流量
    3. 需要使用更高级的绕过技术

## 10.6 高级技巧

### 10.6.1 使用Nmap脚本引擎（NSE）深入检测服务

Nmap的脚本引擎（NSE）提供了丰富的脚本，可以对特定服务进行更深入的**检测**。

!!! info "常用服务检测脚本"
    ```bash
    # 检测HTTP服务的详细信息和漏洞
    nmap --script http-enum,http-headers,http-methods -p 80,443 <target>
    
    # 检测SSH服务的安全性和版本信息
    nmap --script ssh-hostkey,ssh-auth-methods -p 22 <target>
    
    # 检测MySQL服务的弱密码和配置问题
    nmap --script mysql-info,mysql-empty-password -p 3306 <target>
    
    # 检测DNS服务的递归查询和缓存投毒风险
    nmap --script dns-recursion,dns-cache-snoop -p 53 <target>
    ```

### 10.6.2 将扫描结果保存为多种格式

Nmap支持将扫描结果保存为多种格式，方便后续分析。

| 参数 | 格式 | 说明 |
|------|------|------|
| `-oN <file>` | 普通文本 | 默认的文本格式 |
| `-oX <file>` | XML | 结构化格式，便于程序解析 |
| `-oG <file>` | Grepable | 便于grep处理的格式 |
| `-oA <basename>` | 全部 | 同时保存三种格式 |

**示例**：

```bash
# 扫描并保存结果
nmap -p 80,443 -sV -oA web-scan 192.168.1.0/24

# 生成文件：
# web-scan.nmap (普通文本)
# web-scan.xml  (XML格式)
# web-scan.gnmap (Grepable格式)
```

### 10.6.3 使用grep提取关键信息

结合shell的grep命令，可以从扫描结果中快速提取所需信息。

!!! info "实用命令示例"
    ```bash
    # 从扫描结果中提取开放了80端口的主机
    nmap -p 80 -oG - 192.168.1.0/24 | grep "80/open" | cut -d' ' -f2
    
    # 提取所有开放SSH服务的主机IP
    nmap -p 22 -oG - 192.168.1.0/24 | grep "22/open" | awk '{print $2}'
    
    # 批量检测Web服务并使用curl获取标题
    for ip in $(nmap -p 80 -oG - 192.168.1.0/24 | grep "80/open" | cut -d' ' -f2); do
        echo "IP: $ip"
        curl -s http://$ip | grep -oP '<title>\K.*?(?=</title>)'
    done
    ```

### 10.6.4 编写自动化扫描脚本

将Nmap命令集成到shell脚本中，实现自动化批量**扫描**。

**示例脚本：批量检测数据库端口**

```bash
#!/bin/bash
# 文件名：check_db_ports.sh
# 用途：批量检测目标网段内的数据库端口

TARGET="192.168.1.0/24"
PORTS="3306,5432,27017,6379"
OUTPUT="db-scan-$(date +%Y%m%d).txt"

echo "[*] 开始扫描数据库端口..." | tee $OUTPUT
echo "[*] 目标网段: $TARGET" | tee -a $OUTPUT
echo "[*] 扫描端口: $PORTS" | tee -a $OUTPUT
echo "----------------------------------------" | tee -a $OUTPUT

nmap -p $PORTS -sV -oN $OUTPUT $TARGET

echo "----------------------------------------" | tee -a $OUTPUT
echo "[*] 扫描完成，结果已保存到 $OUTPUT" | tee -a $OUTPUT
```

**使用方法**：

```bash
chmod +x check_db_ports.sh
./check_db_ports.sh
```

### 10.6.5 针对特定服务的深入扫描策略

不同服务的扫描策略有所不同，下面是一些针对性建议：

!!! tip "Web服务（HTTP/HTTPS）"
    ```bash
    # 全面扫描Web服务
    nmap -p 80,443,8080 -sV --script http-* -oA web-audit target.com
    ```
    
    重点检测：
    - Web服务器类型和版本（Nginx/Apache/Tomcat）
    - HTTP方法（PUT/DELETE是否开启）
    - 常见漏洞（如目录遍历、默认页面）
    - SSL/TLS配置（证书有效性、加密套件强度）

!!! tip "数据库服务"
    ```bash
    # 审计数据库服务安全配置
    nmap -p 3306,5432,27017,6379 -sV --script mysql-*,postgresql-*,mongodb-*,redis-* target
    ```
    
    重点检测：
    - 是否允许空密码或弱密码
    - 是否对外开放
    - 版本是否存在已知漏洞

!!! tip "DNS服务"
    ```bash
    # 检测DNS服务配置
    nmap -p 53 -sV --script dns-* target
    ```
    
    重点检测：
    - 是否允许递归查询（可能被用于DDoS放大攻击）
    - DNS缓存投毒风险

## 10.7 常见问题 FAQ

??? question "Q1：为什么扫描结果显示所有端口都是filtered？"
    A：可能的原因包括：
    
    1. **防火墙**完全阻断了扫描流量。目标主机前的防火墙丢弃了所有到达的探测包。
    2. 目标主机不在线。
    3. 使用了过于激进的扫描参数，触发了入侵防御系统（IPS）的阻断。
    
    解决方法：
    - 使用 `-Pn` 跳过主机发现
    - 使用 `-sA`（ACK扫描）尝试绕过防火墙
    - 降低扫描速度（`-T0` 或 `-T1`）
    - 使用分片（`-f`）或诱饵（`-D`）技术

??? question "Q2：扫描速度很慢，如何提高效率？"
    A：可以采取以下优化措施：
    
    1. 使用 `--top-ports` 或 `-F` 仅扫描常见端口，而非全端口
    2. 使用 `-n` 禁用DNS解析
    3. 使用 `--min-rate` 和 `--max-rate` 控制发包速率
    4. 使用 `-T4` 或 `-T5` 提高时序模板（仅在授权测试中使用）
    5. 并行扫描多个目标（`nmap <targets> --min-parallelism 32`）
    
    ```bash
    # 快速扫描常见Web端口
    nmap -n -T4 -p 80,443,8080 --open target.com
    ```

??? question "Q3：如何只显示开放（open）的端口？"
    A：使用 `--open` 参数可以仅显示状态为open的端口。
    
    ```bash
    nmap -p 1-1000 --open 192.168.1.100
    ```

??? question "Q4：扫描结果中的'service'和'version'字段是什么意思？"
    A：
    - **service**：Nmap根据端口号猜测的服务名称。例如，80端口对应http，22端口对应ssh。
    - **version**：通过 `-sV` 参数实际探测到的服务版本信息。
    
    两者可能不一致。例如，某服务配置在非默认端口上（如SSH运行在2222端口），此时service字段显示的是端口号对应的默认服务（2222对应未知），而version字段会显示实际探测到的服务（SSH）。

??? question "Q5：如何扫描IPv6地址？"
    A：使用 `-6` 参数启用IPv6扫描。
    
    ```bash
    # 扫描IPv6地址的80端口
    nmap -6 -p 80 fe80::1
    
    # 扫描IPv6网段
    nmap -6 -p 80 2001:db8::/64
    ```

??? question "Q6：Nmap扫描会被发现吗？"
    A：是的，Nmap扫描活动很可能被目标网络的入侵检测系统（IDS）、入侵防御系统（IPS）或日志系统记录。
    
    原因如下：
    1. Nmap会产生大量异常的网络流量
    2. 某些扫描技术（如SYN扫描）会留下明显的特征
    3. 现代安全设备都有针对Nmap特征的检测规则
    
    如果在授权测试中进行扫描，应提前告知对方安全团队。如果是未授权扫描，可能面临法律风险。

??? question "Q7：如何判断扫描结果是否准确？"
    A：端口扫描结果的准确性受多种因素影响：
    
    1. **防火墙/过滤器**：可能导致端口状态误报为filtered
    2. **网络延迟/丢包**：可能导致误报为closed
    3. **速率限制**：某些服务会限制连接频率，导致漏报
    
    建议：
    - 对关键目标进行多次扫描对比
    - 结合多种扫描技术（TCP Connect、SYN、ACK等）交叉验证
    - 使用 `-sV` 进行服务版本检测，确认端口上运行的实际服务
    - 从多个源IP进行扫描，排除网络路径的影响

??? question "Q8：可以在Windows上运行Nmap吗？"
    A：可以。Nmap官方提供了Windows版本的安装包。
    
    下载地址：https://nmap.org/download.html
    
    Windows版的Nmap功能与Linux版基本一致，但某些高级特性（如部分NSE脚本）可能受限。
    
    本书示例主要基于Linux环境，但命令在Windows版Nmap中同样适用。

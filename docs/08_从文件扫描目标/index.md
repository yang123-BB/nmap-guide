## 概述

### 场景引入：防火墙对端口扫描的影响

在现代网络安全环境中，防火墙和入侵检测/防御系统（IDS/IPS）几乎无处不在。作为网络安全从业者或渗透测试人员，您经常会遇到这样的情况：

**场景 1：端口状态显示 `filtered`**

您使用 Nmap 对目标网络进行端口扫描，发现大量端口显示为 `filtered` 状态，无法确定这些端口是开放、关闭还是被防火墙阻止。这使得您无法准确评估目标的攻击面。

**场景 2：扫描被防火墙拦截**

您发起的 Nmap 扫描在几秒钟内就被目标防火墙检测并拦截，导致扫描中断或结果不准确。防火墙的入侵防御系统（IPS）识别出了 Nmap 的特征签名，并采取了阻断措施。

**场景 3：漏报安全隐患**

由于防火墙规则配置不当，某些端口实际上是对外开放的，但标准的 Nmap 扫描无法检测到这些端口，导致安全评估结果不完整，潜在的安全隐患被遗漏。

**为什么需要学习防火墙扫描技术？**

1. **准确评估安全态势**：绕过防火墙限制，获取真实的端口开放情况
2. **验证防火墙规则**：测试防火墙配置是否有效，是否存在规则绕过的可能
3. **渗透测试需要**：在授权的情况下，模拟攻击者绕过防火墙的手法
4. **安全加固验证**：验证安全防护系统的有效性

!!! warning "合法性和道德要求"
    本章介绍的所有技术**仅可用于授权的渗透测试或自己的系统测试**。未经授权对第三方系统进行扫描属于违法行为，可能违反《网络安全法》、《计算机信息系统安全保护条例》等法律法规。请确保在合法合规的前提下使用这些技术。

## 背景知识

### 防火墙的基本工作原理

防火墙是网络安全体系中的第一道防线，其核心功能是**根据预定义的安全规则控制网络流量的进出**。

#### 防火墙的类型

| 防火墙类型 | 工作层次 | 工作原理 | 优点 | 缺点 |
|-----------|---------|---------|------|------|
| 包过滤防火墙（静态） | 网络层、传输层 | 基于 IP、端口、协议等静态规则 | 性能好、成本低 | 容易被检测、无状态 |
| 状态检测防火墙 | 网络层至应用层 | 跟踪连接状态，动态过滤 | 安全性高、功能强 | 性能开销大 |
| 应用代理防火墙 | 应用层 | 代理应用层流量 | 安全性最高 | 性能差、配置复杂 |
| 下一代防火墙（NGFW） | 全层次 | 深度包检测（DPI）、应用识别 | 功能全面 | 成本高、性能要求高 |

#### 包过滤规则（基于 IP、端口、协议）

包过滤防火墙通过检查数据包的以下字段来决定是否允许通过：

- **源 IP 地址**：允许或拒绝来自特定 IP 的数据包
- **目标 IP 地址**：允许或拒绝发往特定 IP 的数据包
- **源端口**：允许或拒绝来自特定端口的数据包
- **目标端口**：允许或拒绝发往特定端口的数据包
- **协议类型**：允许或拒绝 TCP、UDP、ICMP 等协议
- **TCP 标志位**：根据 SYN、ACK、FIN 等标志位进行过滤

**示例规则：**

```bash
# 允许内部网络访问外部的 HTTP/HTTPS
iptables -A FORWARD -s 192.168.1.0/24 -p tcp --dport 80 -j ACCEPT
iptables -A FORWARD -s 192.168.1.0/24 -p tcp --dport 443 -j ACCEPT

# 拒绝外部对内部的高端口访问
iptables -A FORWARD -d 192.168.1.0/24 -p tcp --dport 1024:65535 -j DROP
```

### 状态检测防火墙（Stateful Firewall）

状态检测防火墙不仅检查单个数据包，还**跟踪连接的状态**，记录连接的上下文信息。

#### 连接状态跟踪

状态检测防火墙维护一个**状态表**，记录所有活动的连接：

| 状态 | 描述 |
|------|------|
| NEW | 新连接，第一个数据包 |
| ESTABLISHED | 已建立的连接 |
| RELATED | 与已有连接相关的新连接（如 FTP 数据连接） |
| INVALID | 无效的数据包 |

#### 状态检测的优势

1. **防御 IP 欺骗**：只允许响应已建立连接的数据包通过
2. **防止端口扫描**：检测到异常连接尝试时可以阻断
3. **应用层过滤**：可以理解应用层协议（如 FTP、HTTP）

**示例：**

```bash
# 允许已建立和相关的连接
iptables -A INPUT -m state --state ESTABLISHED,RELATED -j ACCEPT

# 只允许新的 SSH 连接
iptables -A INPUT -p tcp --dport 22 -m state --state NEW -j ACCEPT
```

### 为什么扫描结果会出现 `filtered` 状态

在 Nmap 扫描中，`filtered` 状态表示**无法确定端口是开放还是关闭**，因为目标没有响应，或者有防火墙/过滤器拦截了探测包。

#### `filtered` 状态的常见原因

1. **防火墙丢弃数据包**（DROP 规则）
   - 防火墙直接丢弃数据包，不返回任何响应
   - Nmap 会等待超时，导致扫描变慢

2. **防火墙返回 ICMP 错误消息**（REJECT 规则）
   - 防火墙返回 ICMP Type 3 Code 13（Administratively Prohibited）
   - Nmap 立即将端口标记为 `filtered`

3. **数据包被 IDS/IPS 拦截**
   - 入侵防御系统检测到扫描行为，主动阻断
   - 可能伴随 IP 黑名单、封禁等防御措施

4. **网络拓扑限制**
   - 路由器 ACL（访问控制列表）阻止了流量
   - 目标主机启用了主机防火墙（如 iptables、Windows Firewall）

#### Nmap 的端口状态分类

| 状态 | 含义 |
|------|------|
| `open` | 端口开放，有应用程序正在监听 |
| `closed` | 端口关闭，但没有防火墙拦截 |
| `filtered` | 无法确定，被防火墙或过滤器拦截 |
| `unfiltered` | 端口可访问，但无法确定开放还是关闭（ACK 扫描） |
| `open|filtered` | 可能是开放，也可能是被过滤（UDP 扫描常见） |
| `closed|filtered` | 可能是关闭，也可能是被过滤（FIN/NULL/Xmas 扫描） |

## Nmap 防火墙探测技术

Nmap 提供了多种技术来绕过防火墙和 IDS/IPS 系统。这些技术通过**修改数据包的特征**来规避检测和拦截。

### 分片扫描（`-f`, `--mtu`）

#### 原理

**IP 分片**是将一个大的 IP 数据包分割成多个小的分片包进行传输。防火墙在重组分片包时可能会遇到困难，从而**无法正确检测包的内容**。

- **`-f`**：将 IP 数据包分割成 8 字节的小片段
- **`--mtu <value>`**：指定分片的大小（必须是 8 的倍数）

#### 使用方法

```bash
# 使用 -f 进行分片扫描（默认 8 字节）
nmap -f -sS 192.168.1.100

# 使用双重分片（更小的分片）
nmap -f -f -sS 192.168.1.100

# 指定 MTU 值（必须是 8 的倍数）
nmap --mtu 24 -sS 192.168.1.100
```

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 可以绕过某些老旧的防火墙和 IDS | 现代防火墙和 IDS 能够重组分片进行检测 |
| 实现简单，Nmap 原生支持 | 分片包可能被丢弃，导致扫描不完整 |
| 对某些严格包过滤有效 | 可能导致网络性能下降 |

!!! note "注意"
    某些操作系统和网络设备会自动重组分片包，因此分片扫描在现代网络中效果有限。

### 诱饵扫描（`-D`）

#### 原理

**诱饵扫描**通过**伪造多个源 IP 地址**（诱饵），使得防火墙和 IDS 难以识别真正的扫描源 IP。目标主机收到的扫描流量看起来来自多个不同的 IP 地址。

- **`-D <decoy1,decoy2,...>`**：指定诱饵 IP 地址列表
- **`-D RND:<number>`**：生成指定数量的随机诱饵 IP
- **`-D ME,<decoy1>,...`**：`ME` 表示真实的源 IP

#### 使用方法

```bash
# 使用 3 个诱饵 IP 进行扫描
nmap -D 192.168.1.10,192.168.1.11,192.168.1.12 -sS 192.168.1.100

# 使用随机生成的 5 个诱饵 IP
nmap -D RND:5 -sS 192.168.1.100

# 将真实 IP 放在诱饵列表中（推荐）
nmap -D 192.168.1.10,ME,192.168.1.12 -sS 192.168.1.100
```

#### 示例输出

```
Starting Nmap 7.94 ( https://nmap.org )
Nmap scan report for 192.168.1.100
Host is up (0.0020s latency).
Not shown: 95 closed ports
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https

Nmap done: 1 IP address (1 host up) scanned in 2.34 seconds
```

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 隐藏真实扫描源 IP | 诱饵 IP 必须是活跃的，否则容易被识别 |
| 增加 IDS/IPS 的分析难度 | 可能违反网络使用政策 |
| 对某些防火墙规则有效 | 扫描速度变慢 |

### 源端口欺骗（`--source-port`）

#### 原理

某些防火墙规则配置不当，可能会**允许来自特定源端口的流量**通过。例如，允许 DNS（端口 53）、FTP（端口 20/21）、HTTP（端口 80）等常用服务的流量。

- **`--source-port <port>`**：指定源端口
- **`-g <port>`**：`-g` 是 `--source-port` 的简写

#### 使用方法

```bash
# 使用源端口 53（DNS）进行扫描
nmap --source-port 53 -sS 192.168.1.100

# 使用源端口 80（HTTP）进行扫描
nmap -g 80 -sS 192.168.1.100

# 使用源端口 20（FTP-DATA）进行扫描
nmap -g 20 -sS 192.168.1.100
```

#### 常见的可利用端口

| 端口 | 服务 | 说明 |
|------|------|------|
| 20 | FTP-DATA | FTP 数据传输 |
| 21 | FTP | FTP 控制连接 |
| 53 | DNS | 域名解析 |
| 80 | HTTP | 网页访问 |
| 123 | NTP | 时间同步 |
| 443 | HTTPS | 加密网页访问 |

!!! warning "注意"
    源端口欺骗的成功率取决于防火墙规则的配置。现代防火墙通常不对源端口进行信任。

### 时序调整（`-T` 模板）

#### 原理

Nmap 的**时序模板**控制扫描的速度和并发度。通过调整时序，可以**降低被 IDS/IPS 检测到的概率**，同时避免对目标网络造成过大负载。

- **`-T0`（Paranoid）**：串行扫描，每次探测之间等待 5 分钟
- **`-T1`（Sneaky）**：串行扫描，每次探测之间等待 15 秒
- **`-T2`（Polite）**：降低扫描速度，减少网络负载
- **`-T3`（Normal）**：默认模式，平衡速度和隐蔽性
- **`-T4`（Aggressive）**：快速扫描，假设网络环境良好
- **`-T5`（Insane）**：极速扫描，可能丢失数据

#### 使用方法

```bash
# 使用 T1 模板（隐蔽扫描）
nmap -T1 -sS 192.168.1.100

# 使用 T2 模板（礼貌扫描）
nmap -T2 -sS 192.168.1.100

# 使用 T3 模板（默认）
nmap -T3 -sS 192.168.1.100
```

#### 时序模板对比

| 模板 | 并行探测数 | 延迟 | 适用场景 |
|------|-----------|------|---------|
| T0 | 1 | 5 分钟 | 高度隐蔽，IDS 规避 |
| T1 | 1 | 15 秒 | 隐蔽扫描 |
| T2 | 较低 | 无 | 避免影响网络性能 |
| T3 | 默认 | 无 | 常规扫描 |
| T4 | 较高 | 无 | 快速扫描（内网） |
| T5 | 最高 | 无 | 极速扫描（可能丢包） |

### 空闲扫描（`-sI`）

#### 原理

**空闲扫描**是一种高度隐蔽的扫描技术，利用**僵尸主机（zombie host）** 来间接扫描目标。扫描流量看起来来自僵尸主机，而非真实的扫描者。

空闲扫描需要满足以下条件：
1. 僵尸主机必须是**空闲的**（没有活跃的网络连接）
2. 僵尸主机的 IP 数据包 ID（IP ID）必须是**递增的**

#### 使用方法

```bash
# 使用空闲扫描（需要指定僵尸主机）
nmap -sI <zombie_host> <target>

# 示例：使用 192.168.1.50 作为僵尸主机扫描 192.168.1.100
nmap -sI 192.168.1.50 192.168.1.100

# 指定端口（默认使用 80 端口）
nmap -sI 192.168.1.50:443 192.168.1.100
```

#### 查找合适的僵尸主机

```bash
# 使用 Nmap 的 ipidseq 脚本检测 IP ID 序列
nmap -p 80 --script ipidseq <candidate_zombie>
```

#### 优缺点

| 优点 | 缺点 |
|------|------|
| 高度隐蔽，真实 IP 不被暴露 | 需要找到合适的僵尸主机 |
| 可以绕过某些防火墙和 IDS | 扫描速度非常慢 |
| 真实扫描源难以追踪 | 可能被某些网络设备拦截 |

!!! note "注意"
    空闲扫描在现代操作系统中成功率较低，因为许多系统使用随机 IP ID。

## 实战演练

### 练习1：基础防火墙探测

#### 目标
学习如何识别防火墙的存在，并解读 `filtered` 状态。

#### 步骤

**步骤 1：进行标准 SYN 扫描**

```bash
nmap -sS -p 1-1000 192.168.1.100
```

**预期输出：**

```
Starting Nmap 7.94 ( https://nmap.org )
Nmap scan report for 192.168.1.100
Host is up (0.0020s latency).
Not shown: 995 filtered ports
PORT     STATE SERVICE
22/tcp   open  ssh
80/tcp   open  http
443/tcp  open  https

Nmap done: 1 IP address (1 host up) scanned in 25.34 seconds
```

**步骤 2：分析扫描结果**

- 如果大部分端口显示为 `filtered`，说明目标可能有防火墙
- 记录开放的端口（如 22、80、443）

**步骤 3：使用 `-v` 参数查看详细信息**

```bash
nmap -sS -p 1-1000 -v 192.168.1.100
```

**预期输出（部分）：**

```
Increasing send delay for 192.168.1.100 from 0 to 5 due to max_successive_timeouts
Discovered open port 22/tcp on 192.168.1.100
Discovered open port 80/tcp on 192.168.1.100
```

#### 思考题

1. 为什么有些端口显示为 `filtered`？
2. 如何判断防火墙是丢弃数据包还是返回 ICMP 错误？

### 练习4：调整时序模板避免被拦截

#### 目标
学习如何通过调整时序模板来降低被 IDS/IPS 检测到的概率。

#### 步骤

## 高级技巧

### 组合多种技术提高成功率

单一技术可能无法绕过现代的防火墙和 IDS/IPS 系统。通过**组合多种技术**，可以显著提高扫描成功率。

#### 示例：组合分片 + 诱饵 + 时序调整

```bash
nmap -f -D RND:5 -T2 -sS -p 1-1000 192.168.1.100
```

**解释：**
- `-f`：分片扫描，绕过某些包过滤规则
- `-D RND:5`：使用 5 个随机诱饵，隐藏真实 IP
- `-T2`：使用礼貌时序，降低被检测概率
- `-sS`：SYN 扫描，快速且不易被日志记录

#### 示例：组合源端口欺骗 + 时序调整

```bash
nmap -g 53 -T1 -sS -p 1-1000 192.168.1.100
```

**解释：**
- `-g 53`：伪装源端口为 DNS（53），绕过基于源端口的过滤
- `-T1`：使用隐蔽时序，每次探测间隔 15 秒

### 使用 `--badsum` 生成错误校验和

#### 原理

`--badsum` 选项会故意生成**错误的 TCP/UDP 校验和**，某些防火墙和 IDS 在检查校验和时会直接丢弃这些包，而不会记录日志。这可以用于：

1. **探测防火墙规则**：观察防火墙是否检查校验和
2. **绕过某些简单的过滤器**：某些老旧系统可能不会检查校验和

#### 使用方法

```bash
# 使用错误的校验和进行扫描
nmap --badsum -sS -p 22,80 192.168.1.100
```

#### 注意事项

- 大多数现代操作系统会丢弃校验和错误的包
- 该技术主要用于探测防火墙行为，而非实际扫描

### 使用 `--data-length` 发送随机数据

#### 原理

某些 IDS/IPS 系统通过**特征匹配**来检测 Nmap 扫描。通过在数据包中**附加随机数据**，可以改变其特征，从而规避检测。

- **`--data-length <number>`**：在发送的数据包中附加指定长度的随机数据

#### 使用方法

```bash
# 在每个数据包中附加 50 字节的随机数据
nmap --data-length 50 -sS -p 22,80 192.168.1.100

# 附加 200 字节的随机数据
nmap --data-length 200 -sS -p 1-1000 192.168.1.100
```

#### 示例

```bash
# 组合多种技术
nmap --data-length 100 -f -D RND:3 -T2 -sS -p 1-1000 192.168.1.100
```

### 其他高级选项

| 选项 | 说明 |
|------|------|
| `--ttl <value>` | 设置 IP 包的 TTL（生存时间）值 |
| `--spoof-mac <mac>` | 伪造 MAC 地址 |
| `--proxies <url1,url2,...>` | 通过 HTTP/SOCKS4 代理链扫描 |
| `--reason` | 显示端口处于某种状态的理由 |
| `--packet-trace` | 显示发送和接收的数据包 |

#### 示例：使用代理链进行扫描

```bash
nmap --proxies http://proxy1:8080,socks4://proxy2:1080 -sS 192.168.1.100
```

## 常见问题

### 1. 为什么我的 Nmap 扫描结果显示大量 `filtered` 端口？

**答：**
大量 `filtered` 端口通常意味着目标网络部署了防火墙或 IDS/IPS 系统。可能的原因包括：

- 防火墙丢弃了探测包（DROP 规则）
- 防火墙返回了 ICMP 错误消息（REJECT 规则）
- IDS/IPS 检测到扫描行为并阻断了连接
- 目标主机启用了主机防火墙

**解决方法：**
尝试使用本章介绍的绕过技术，如分片扫描、诱饵扫描、源端口欺骗等。

---

### 2. 分片扫描在现代网络中还有用吗？

**答：**
分片扫描在**现代网络环境中的效果有限**。原因包括：

- 现代防火墙和 IDS 能够重组分片包并进行检测
- 某些操作系统和网络设备会自动重组分片包
- 分片包可能被路径上的路由器丢弃

**建议：**
可以尝试使用，但不要完全依赖该技术。建议组合多种绕过技术。

---

### 3. 诱饵扫描是否合法？

**答：**
诱饵扫描的合法性取决于您的使用场景：

- ✅ **合法**：在授权的渗透测试中，对自己的系统或获得书面授权的系统进行测试
- ❌ **非法**：对未经授权的第三方系统进行扫描

**注意：**
即使是在授权测试中，使用诱饵扫描也可能违反某些组织的网络使用政策。建议事先获得明确授权。

---

### 4. 如何判断目标是否部署了状态检测防火墙？

**答：**
可以通过以下方法判断：

1. **使用 ACK 扫描（`-sA`）**：
   - 如果返回的端口状态是 `unfiltered`，说明防火墙允许该端口的流量通过
   - 如果返回的端口状态是 `filtered`，说明防火墙阻止了该端口的流量

2. **观察扫描延迟**：
   - 状态检测防火墙通常会对异常流量进行更严格的检查，导致扫描延迟增加

3. **查看 ICMP 错误消息**：
   - 如果收到 ICMP Type 3 Code 13（Administratively Prohibited），说明有防火墙或过滤器

**示例：**

```bash
nmap -sA -p 1-1000 192.168.1.100
```

---

### 5. 空闲扫描找不到合适的僵尸主机怎么办？

**答：**
空闲扫描对僵尸主机的要求较高：

1. **僵尸主机必须是空闲的**（没有活跃的网络连接）
2. **IP ID 必须是递增的**（某些操作系统使用随机 IP ID）

**解决方法：**

1. 使用 Nmap 的 `ipidseq` 脚本扫描候选僵尸主机：
   ```bash
   nmap -p 80 --script ipidseq 192.168.1.0/24
   ```

2. 选择老旧的操作系统（如 Windows XP、旧版 Linux）作为僵尸主机，它们的 IP ID 通常是递增的

3. 如果找不到合适的僵尸主机，可以考虑使用其他绕过技术（如分片、诱饵等）

---

### 6. 使用 `--badsum` 选项有什么实际用途？

**答：**
`--badsum` 选项的主要用途包括：

1. **探测防火墙和 IDS 的行为**：
   - 观察防火墙是否检查校验和
   - 某些防火墙可能不会记录校验和错误的包

2. **绕过某些简单的过滤器**：
   - 某些老旧的系统可能不会检查校验和

3. **安全研究**：
   - 用于测试网络设备对异常包的处理能力

**注意：**
大多数现代操作系统会直接丢弃校验和错误的包，因此该技术在实际扫描中效果有限。

---

### 7. 如何避免被 IDS/IPS 检测到？

**答：**
虽然没有绝对的方法可以完全规避 IDS/IPS，但可以采取以下措施降低被检测到的概率：

1. **调整时序模板**：使用 `-T0` 或 `-T1` 降低扫描速度
2. **使用诱饵扫描**：隐藏真实的扫描源 IP
3. **分片扫描**：绕过某些基于特征的检测
4. **附加随机数据**：使用 `--data-length` 改变数据包特征
5. **使用代理链**：通过 `--proxies` 隐藏真实 IP
6. **避免在业务高峰期扫描**：减少被注意的可能性

**重要：**
即使采取了这些措施，也不能保证完全不被检测到。请确保在合法授权的前提下进行测试。

---

### 8. 现代防火墙和 IDS/IPS 系统能够检测哪些 Nmap 绕过技术？

**答：**
现代防火墙和 IDS/IPS 系统通常能够检测以下技术：

| 技术 | 检测难度 | 说明 |
|------|---------|------|
| 分片扫描 | 低 | 现代 IDS 能够重组分片包 |
| 诱饵扫描 | 中 | 可以通过流量分析识别 |
| 源端口欺骗 | 低 | 简单的规则即可检测 |
| 时序调整 | 中 | 基于流量特征的检测 |
| 空闲扫描 | 高 | 难以检测，但成功率低 |
| `--badsum` | 低 | 大多数系统会丢弃错误校验和的包 |
| `--data-length` | 中 | 可以改变特征，但某些 IDS 能够识别模式 |

**建议：**
不要依赖单一技术，建议组合多种技术并使用最新的绕过方法。

## 总结

### 核心知识点

1. **防火墙基本原理**：
   - 包过滤防火墙、状态检测防火墙、下一代防火墙的区别
   - 防火墙规则基于 IP、端口、协议等字段进行过滤

2. **`filtered` 状态的含义**：
   - 表示无法确定端口是开放还是关闭
   - 通常由防火墙丢弃数据包或返回 ICMP 错误消息导致

   - 使用 `--data-length` 发送随机数据以改变特征
